# Очередь, каталог и мотив решения

## Контракт этого среза

`/editorial` показывает только `candidate` с `editorial_version = 0`, до 50 за раз. После успешного select/reject/hold/revise версия увеличивается и сюжет уходит из новых. После ошибки сохранения он остаётся. Это смена представления, не удаление данных. Новая версия источника сама по себе не обнуляет человеческое решение.

`/editorial/stories` — общий приватный каталог: поиск без учёта регистра по заголовку, canonical DOI/arXiv, aliases и сохранённым человеческим мотивам; фильтры области, lifecycle status и последнего человеческого решения; страницы по 20. `%`, `_` и backslash ищутся буквально; `*` поддерживается PostgREST как wildcard. Reject и hold разделяются фильтром решения, хотя оба сейчас дают lifecycle status held. Сортировка стабильная: created_at DESC, id ASC. Поиск выполняется в БД до pagination, не только среди первых 50 записей.

Migration 007 создаёт read-only `security_invoker` view. Все таблицы продолжают применять RLS текущего пользователя, включая текст мотивов и source aliases. Аноним не имеет SELECT; outsider не видит строк; reviewer читает без права решать. Сохранение перепроверяет роль и optimistic version. Возврат после формы допускает только очередь или каталог с известными фильтрами. Нет service-role в web.

Критерии готовности: сохранённый сюжет исчезает из новых, находится в каталоге, фильтры работают вместе, вторая страница содержит остаток, повторное рассмотрение сохраняет прошлые причины. Проверено HTTP integration с настоящими локальными Auth/Next/DB и SQL RLS tests. Migration 007 применена только локально; cloud 005–007 остаются отдельным шагом после review.

## Что делаем с Motivo

Есть две разные памяти:

- **Редакционная:** append-only `editorial_decisions` с автором, временем, policy version, решением и причиной. Она отвечает, почему тему выбрали, отложили или отклонили. В каталоге можно найти её и принять новое решение, сохранив историю.
- **Научная:** claims, точные цитаты/locators, evidence и концепты из проверенных документов. Мотив редактора не превращается в доказательство научного утверждения. Даже отвергнутый сюжет может позже дать полезный проверенный контекст, но это отдельный research/review.

Работает сейчас: `gold:export:local` переносит последнее человеческое решение, мотив, decision ID и policy version в `selection-gold/2`, сохраняя историю. Agent votes и publication approval не заменяют человеческую selection label. Только select/reject — завершённые binary labels; hold/revise остаются неразрешёнными. Hold не означает автоматически «годится как контекст». Пул до 21 AI + 9 physics из последних 100 сюжетов — metadata selection pool, не claim-verification gold set. Перед сравнением моделей фиксировать отдельный snapshot: повторный экспорт может изменить состав при новом intake. Модельный ranking нельзя показывать до независимой человеческой разметки.

Следующий шаг после budget ledger: сравнивать ranking с этим snapshot, разбирать false select/reject и группировать причины (повтор, старая новость, вне темы, слабая доказательная база, нужен первоисточник, хороший контекст). Коды причин и автоматические отчёты пока не реализованы. Изменение policy/prompt оформляется отдельной версией и проходит тот же эталон; автоматического переобучения по одному комментарию нет. Свободный текст мотива — untrusted data, не команды для агента.

## Повторный анализ

Сейчас редактор находит сюжет в каталоге, выбирает «Solicitar revisión» и пишет новый мотив, например «появилась независимая репликация; проверить прежний вывод». Это сохраняет новую редакционную запись и переводит сюжет в review; **не запускает ещё не реализованный научный research worker**.

Дальше триггеры для отдельной review-очереди: новая версия первоисточника, correction/retraction, независимая репликация, найденный первичный документ для институционального релиза, значимое изменение policy. Триггер хранит конкретное основание и snapshot источника; не стирает старое решение и не возвращает всё отвергнутое в новые. Scheduler и такие автоматические триггеры ещё не подключены. Несогласие модели с редактором само по себе не повод отменять решение.

Ближайший самостоятельный срез — atomic budget ledger reserve → settle/release с лимитами и crash recovery. Только после его проверки подключать платный research и blind comparison Claude/OpenAI. Затем evidence-backed ES/EN revisions; далее испанский видеопилот.
