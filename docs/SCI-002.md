# SCI-002 — Primary metadata and reviewed identity resolution

Implemented on merged SCI-001 (`d8d8c40`). Baseline: SCI-002-PLAN.md. HLD, MVP, language/video gates and budget stay unchanged. Free bibliographic metadata only; no paid LLM, scientific verification, full-text crawling or production configuration changes.

## Four distinct layers

1. `external_reviews` / `external_review_items`: immutable secondary Markdown and claimed extraction; always unverified.
2. `metadata_snapshots`: immutable primary-service response, exact SHA-256, normalized fields, adapter version, first retrieval timestamp. `metadata_fetches` records each actual retrieval/outcome and snapshot reference; identical responses reuse a snapshot. A 24-hour successful-fetch cache avoids repeated calls, including when a previously seen payload returns again.
3. `identity_proposals` + `identity_confirmations`: explicit arXiv DOI reference and a matching Crossref DOI record, exact evidence snapshot IDs, human actor/reason, append-only outcome. No title/author-only proposals. The UI shows title/author consistency warnings and current exact matches. An editor reviews and confirms the relationship; warnings require judgment, not model confidence. Confirmation atomically rechecks sorted identity locks and aliases. Two existing Sources yield `conflict`, preserving both; this PR does not implement a destructive source/story merge.
4. Scientific claims remain unverified. Metadata does not establish full-text access, peer review, reuse rights, experimental validity or scientific truth. No claims, published conclusions, revisions or approvals are changed.

## Adapters and worker

`packages/sources/src/metadata.ts` constructs only HTTPS `export.arxiv.org/api/query?id_list=...&max_results=1` and `api.crossref.org/works/{encoded DOI}` requests. Canonical IDs are reused. Both adapters verify the returned identity. The existing HTTPS transport pins validated public IPv4 DNS to the real connection, rejects redirects/credentials/ports/unapproved routes, has a 20-second timeout, identity encoding and a 2 MB response cap; normalized output is capped at 256 KiB, 500 authors/categories and a 2,000-character title. arXiv rejects DTD/entities/malformed XML. No URL from metadata is fetched.

arXiv: title/authors/abstract/categories, original publication and updated timestamps, version returned by the API, DOI, journal reference. The API response is not a complete version history; unavailable historical versions are not invented.

Crossref: title/authors/journal, publisher/type/volume/issue/page/article-number/ISSN/ISBN where supplied, supplied date structures (including partial date-parts), created/indexed/deposited separately, relations and update-to records. Created/indexed never substitute for publication. Relationship/update metadata is retained for review, not scientific endorsement.

Editor-only `request_metadata` enqueues `metadata_enrichment` in the existing queue, idempotent per identity/UTC day. `worker:local` handles it with the existing job heartbeat/lease/retries. Metadata jobs share the exact existing arXiv provider lock/cooldown with feeds; Crossref adds a row to that same lock table, not a new infrastructure service. 429/503 honor bounded Retry-After; parse/network failure records status 0 and a 60-second cooldown. Busy provider or unavailable data fails/defer-retries through the existing bounded queue, never reports fabricated success. There is no scheduled poller or automatic paid stage.

New feed DOI suggestions no longer create aliases automatically: fresh feed intake persists the arXiv canonical alias only. Existing aliases/Stories are preserved for compatibility and do not become human-verified relationships retroactively. Run enrichment/review to establish an explicit confirmation. Two ingestion regression assertions now check this deliberately stricter behavior.

## Editorial workflow

From inbox/catalog Source → **Metadatos primarios y relaciones revisadas**, or imported section → **Metadatos primarios, identidad y eventos**:

1. Search saved metadata or enqueue canonical DOI/arXiv lookup; execute `npm run worker:local` and reload. GET/read-only preview never dispatches a network request or writes a decision.
2. Compare original extraction with fetched metadata, retrieval date/hash, exact Source match, relationship evidence and conflicts.
3. For a missing-identity active-scope section, select a snapshot and supply a reason; confirm. `resolve_pending` reuses `create_candidate`, Source/Story/aliases and normalization queue. `pending_resolutions` appends version/previous ID/snapshot/actor/reason/command; the imported item's selected_identity, story_id, disposition and extraction remain unchanged. A correction appends another version. Stale expected versions fail; identical command replay returns the same record; changed reuse of a command fails.
4. Register an explicit DOI↔arXiv proposal, then separately confirm it with a reason. Conflicting Sources remain unresolved. A later confirmation attempt rechecks current state; no background merge.

Reviewer reads only; outsider/anonymous cannot read private data. Server Actions use the user's session, with membership checked again in each RPC. Browser-submitted metadata JSON cannot create a snapshot. Web has no service-role key. Existing SCI-001 actor/document/payload signing remains intact.

Lists are deliberately bounded (100 snapshots/pending items/proposals; 200 recent histories). This is a pilot console, not an unlimited metadata search engine. Older originals remain accessible by archive/item ID. Large-scale paging/search and source conflict-merging tools are follow-ups.

## Scientific observations and reconciliation

`review_event_observations` preserves each extracted event by immutable item ID + ordinal, including pending sections. Migration backfills retained SCI-001 extraction in full, including legacy pending sections with more than 20 events, without rewriting original records or scientific event UUIDs. New sections in every scope are limited to 20 events. Previously collapsed observations that still exist in extraction regain separate observation identities; data absent from original extraction is not invented. Legacy cross-report dated deduplication is retained. New undated/unversioned scientific-event keys also include the ordinal, so two same-type undated events in one item never collapse. The parser retains multiple explicit `Event:` markers. Re-import of already saved extraction that differs from the corrected parser is held by SCI-001 provenance conflict checks; it never overwrites history.

Reconciliation is a separate human decision. An editor selects observations (including related sections of the same Story), a primary snapshot, kind, provider basis and reason. Supported anchors: arXiv `initialPublished`, `version`; complete Crossref `published`/`published-online`/`published-print` date-parts; an explicit correction/retraction `update:N` entry. Unknown/partial dates alone cannot create a canonical event. Source/kind/explicit reference mismatches and contrary reported dates/versions are held. Metadata cannot anchor an arbitrary experimental-result or independent-replication event; those stay unlinked until richer evidence exists.

`canonical_scientific_events` identifies the provider-backed event. `event_reconciliations` is append-only per observation with expected version, previous link, evidence snapshot, actor and reason. Multi-observation confirmation is one atomic bounded command. Replay is exact and idempotent; extending a previously used command or stale correction fails. Linking observations does not assert that the reported scientific conclusion is true. `scientific_events.needs_review`, original dates, raw extraction, published status/version and approvals remain intact.

Migration **011 is local only**. No cloud installer/config changes. It reuses 009/010 without editing them. Existing local data is not reset. Live activation/migration requires a separate explicit approval; signing configuration from SCI-001 still applies.

Offline demonstration writes ignored `artifacts/metadata/demonstration.json` and rolls back its transaction. It covers imported arXiv enrichment, Crossref DOI, human-confirmed relationship, two-Source conflict, pending approval/history, repeated enrichment/import, multiple undated observations in one item, reconciliation and published-state preservation. HTTP integration covers genuine Next Server Actions, preview without writes, pending confirmation/replay, original immutability, reviewer/outsider denial and CSRF. Queue and budget regressions remain separate.

Opt-in real-network smoke succeeded on 31 October 2026 for arXiv `1706.03762` and DOI `10.1038/s41586-021-03819-2`. It stores an ignored hash/timestamp report, does not add these papers to the editorial pool and makes zero paid calls. Network tests are not part of deterministic CI.

Primary references: [arXiv API manual](https://info.arxiv.org/help/api/user-manual.html), [arXiv terms/rate limits](https://info.arxiv.org/help/api/tou.html), [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/). Metadata is publisher/service-supplied bibliographic evidence and may itself contain errors; human decisions retain the exact snapshot used.

## Readiness for the first real content-production pilot

Available: real-source intake and review import, Auth/RLS/editorial selection memory, exact canonical identities and reviewed links, original/primary metadata provenance, pending resolution, reviewed event links, queue/leases, production budget ledger and release-gate domain contracts. The existing local metadata brief and synthetic dossier/article/script demos are tooling foundations, not completed scientific content production.

Minimum missing slice before a real pilot:

1. Freeze a human-selected primary Source/version package; obtain permitted document text and persist access scope/rights. Mark abstract-only evidence explicitly.
2. Persist versioned Research Dossier with located short quotes, typed claims, methodology, limitations and what authors do not claim; independent scientific review against those documents. A bibliographic confirmation cannot satisfy this gate.
3. Build/persist an Editorial Brief from the reviewed dossier: angle, audience, novelty, approved claims and caveats; human approval bound to its exact inputs.
4. Metered draft adapters and immutable ES/EN Article Drafts from those approved claims; per-language alignment review, no automatic approval/publication.
5. Spanish Video Script from the same frozen dossier/approved article inputs, scene claim IDs and caveats, separate human review. Voice/assets/render/upload remain subsequent video work.

Recommendation: next is one narrow, human-supervised primary-document → dossier → brief pilot, followed by draft adapters after the evidence boundary is working. No full content-production pipeline is implemented within SCI-002. Original manuscript preparation/human-controlled arXiv submission remains separate FUT-ARXIV-001, outside HLD/MVP.
