# SCI-004 — Evidence-based content drafts

31 October 2026. Base verified: PR9 merged as `dc93540`; PR10 merged as `b421681` on master. This slice adds local migration 013, not cloud installation or production configuration. Public pages remain synthetic demos; no automatic publication.

## Trusted evidence input

`content_generation_input(brief_id)` loads the immutable dossier/document, final Editorial Brief, exact current scientific review IDs and whole-dossier approval from PostgreSQL. It rejects preliminary, unapproved and stale inputs. It uses the existing research-story advisory lock, so new document intake, dossier revision or claim review invalidates subsequent generation/save/review. The returned snapshot/hash retains dossier/brief versions and hashes, document checksum/scope/rights, reviewed findings (including narrowed wording), located evidence and mandatory caveats. Extracted citations never become independent scientific verification; claims.status is unchanged.

The writer is instructed that only approvedFindings authorize scientific assertions; the reviewed dossier supplies context, not additional findings. Rejected and unsupported claims cannot be referenced by output. The model may still misinterpret evidence: structural mapping checks are not scientific truth or a semantic entailment evaluator.

## Three independent outputs

`article_es` and `article_en` each require scientific_question, background, methods, results, significance, limitations, remaining_questions and original_sources. All paragraphs conservatively require approved claim UUIDs, including contextual explanations. The original reference list is also displayed from the authoritative brief. Each language has its own existing articles revision sequence and separate review.

`script_es` uses VIDEO-001's five scene kinds and maps into `HybridScene` through `contentSceneDrafts`. Main scenes must cover all approved findings and mandatory caveats without any presenter inserts. Inserts are optional and at most eight seconds; concept visuals need explanatory labels; a scientific caveat scene is required. Main estimated duration is at least 360 seconds and total at most 480; the 780–1200-word bound is a draft planning check, not measured TTS timing. Assets/audio/render/scientific and visual scene approvals remain pending, never fabricated from a text review.

Draft flags cover schema/language/section errors, unmapped/unapproved claims, missing/unknown caveats, model-reported unsupported statements, new numeric literals absent from approved findings/evidence, optional-presenter and timing failures. Numeric checking is deliberately conservative: it does not establish unit equivalence, statistical meaning or completeness, and it cannot recognize all hallucinations. A paragraph can cite a real claim yet distort it. Human review of every mapping, quantity, caveat and translation remains mandatory. Caveat IDs alone do not prove faithful caveat wording.

## Budget and provider provenance

The existing Gemini adapter now exposes bounded metered generation. `countTokens` checks the complete system/prompt/schema request before reservation. Text input is capped at 256 KiB/20,000 tokens, output at 16,384 tokens, response at 1 MiB, request runtime at 120 seconds. Only the fixed Google endpoint is used, redirects fail, and no tools, search, media or explicit cache API are requested. No provider/model availability is assumed from a configured name.

Every paid call uses the existing ledger reserve/start/settle path under category content. Reservation covers input/output ceilings using the configured current paid-tier tariff card for the exact model. Actual uncached, cached, candidate and thinking tokens are retained; integer microdollar calculations round each priced component upward. Costs are computed from provider-reported usage and the configured rate card, not invented invoice totals. The template contains null rates and is deliberately nonexecutable. A tiered/discounted/free account needs an explicitly supported reviewed billing configuration; the adapter does not silently assume zero cost or credits.

Raw successful HTTP response bytes are archived before JSON/usage/schema parsing. Provider response ID, raw hash, requested model, prompt/schema version, input hash, ceilings, price-card version, usage and measured request duration are preserved. A bounded malformed output with valid usage is recorded and settled before being rejected as a draft. Missing/unsupported usage, timeout, failed persistence or ambiguous settlement holds the operation for reconciliation with funds retained; no automatic paid replay. Local raw receipts are ignored private artifacts. Overflow/transport failures can have unknown bills and require provider-side reconciliation.

Receipts are immutable and written only through a worker RPC. After ledger settlement, a separate save RPC parses the stored response itself, recomputes authoritative flags and creates immutable rows in existing articles/scripts plus content_drafts lineage. It does not accept client extraction JSON. Repeating a settled operation reuses its receipt/revision. An uncertain operation never becomes a new paid request automatically. A persisted request_revision on the latest draft becomes explicit feedback in the next writer request/key; it creates a new revision and inherits no approval.

API references checked for implementation: [countTokens request](https://ai.google.dev/api/tokens), [generation and usage metadata](https://ai.google.dev/api/generate-content), [current pricing](https://ai.google.dev/gemini-api/docs/pricing). Rates must be reviewed again for the chosen model before running.

## Human review

`/editorial/content` shows separate ES/EN/script revisions, prose/scenes and mappings, authoritative findings/located quotes, required caveats, input/output hashes, provider provenance and append-only review history. Current human editor/reviewer may approve, reject or request revision. Approval requires all four explicit checks: claim alignment, language quality, scientific caveats and quantitative values. Blocking structural flags require a corrected new revision. Commands bind exact input/output hashes and expected review version; replay is idempotent, stale/conflicting commands fail. The worker cannot execute the human review RPC or directly insert reviews. Outsiders and anonymous users cannot read drafts/receipts/reviews. Existing selection and budget privileges remain unchanged.

Text approval is not article publication, independent verification, media-rights clearance, voice approval or final MP4 approval. No publisher is implemented by this slice. A new evidence package requires fresh generation/review; immutable history remains visible but cannot be approved against stale inputs.

## Local operation

Use Docker/local Academy 563xx, migrations through 013 and an ignored `.env.local-worker` from `db:local:env`. Store Gemini credentials/model in ignored `.env.local`. `content:local` loads `.env.local` first, then local worker configuration; it refuses any Supabase URL except the local Academy. Set `CONTENT_PRICE_CARD` to a privately reviewed JSON copy of `config/content-prices.template.json`; never place API keys in a tariff file. Configure the current ledger period with existing budget tooling. Do not change cloud Auth or migrations for this test.

```powershell
npm run content:local:status -- <dossier-uuid>
npm run content:local -- <current-final-brief-uuid> all --preflight
npm run content:local -- <current-final-brief-uuid> all
```

Status and preflight make zero model-generation calls. Running all creates three separately metered drafts; prior successful drafts remain when a later stage fails. Existing production_jobs can also run stage content_generation with `{ "briefId": "...", "kind": "article_es" }`; prices/keys come from trusted worker configuration, never job-supplied paths or client JSON. Existing lease heartbeat remains active. A rerun of a dispatched/uncertain operation is held or recovers a settled receipt; new human revision feedback is an explicit new request.
