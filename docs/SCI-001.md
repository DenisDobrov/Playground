# SCI-001 — External Research Review Import

Дата: 30 октября 2026. Ветка `codex/sci-001-review-import`, основание — master после merge PR6. Это дополнение текущего HLD, не замена архитектуры.

## Исходная оценка

HLD доступен: `HLD.md`, с уточнениями ES/EN, редакционной памяти и production tooling. Прочитаны `IMPLEMENTATION.md`, `BACKLOG.md`, `INGESTION.md`, `SUPABASE.md` и migrations 001–008.

| Компонент | Текущее состояние и переиспользование |
|---|---|
| Discovery | arXiv/NASA metadata intake, Source/Story, canonical DOI/arXiv и aliases, нормализация и lease queue |
| Research | Типы dossier/claims/evidence и низкоуровневый Gemini adapter; научная проверка и paid workflow ещё не подключены |
| Editorial | Supabase session/membership, editor/reviewer, Server Actions, create_candidate, record_selection, новые/каталог |
| Publishing | Release contracts и synthetic public pages; live publisher отсутствует и импорт его не включает |
| Budget | Atomic ledger PR6 сохранён; парсер не вызывает провайдера и не резервирует выдуманный LLM expense |

Конфликты: прежняя модель не хранит исходный внешний обзор/секции; несколько ссылок в одной секции не доказывают идентичность работ; прежний selection RPC запрещает менять published story. Поэтому добавлены только оригинал/selected items/reported events; aliases не сливаются по тексту отчёта, а опубликованный материал не меняется. Домены ai/physics переиспользуются, категории fundamental physics/astro-cosmology/quantum computing относятся к physics. Клиническая AI-тема остаётся вне scope по действующей политике медицины.

## Использование

В подключённой редакции открыть `/editorial/imports` через «Informes externos».

1. Выбрать заявленный источник ChatGPT/другой внешний обзор.
2. Вставить Markdown **или** загрузить `.md`/`.markdown`, до 256 KiB.
3. Подготовить preview. Он выполняет только parsing и RLS-protected lookup существующих publications/stories; не создаёт ни Story, ни review record, ни job.
4. Просмотреть количество новых/совпадающих/потенциальных дублей, будущих тем, отсутствующих primary sources и секций для ручной проверки. Счётчики могут пересекаться.
5. Выбрать секции и primary identity. При неоднозначности нужно выбрать DOI/arXiv либо оставить идентификацию на потом. Для совпавшего сюжета можно отдельно запросить review при новом событии.
6. Подтвердить. Server Action повторно проверяет Auth/role, заново разбирает исходный текст и проверяет выбор; SQL RPC атомарно сверяет identities и сохраняет selection.
7. Страница `/editorial/imports/<id>` показывает выбранные секции, links к каталогу, reported events, источник/время/parser/hash и полный оригинал как escaped plain text. Оригинал также доступен по ссылке из карточки сюжета в каталоге.

Reviewer читает архив, но не готовит и не подтверждает импорт. Аноним/outsider не читают оригиналы. Обычный Preview deployment остаётся demo; кнопки не симулируют успешную запись без live configuration.

## Parsing и provenance

Основной формат — английские numbered story headings `# 1. Title` / `## 1. Title` либо `Story: Title` с What changed/Summary, Why it matters, Hype check/Limitations и Assessment. До 50 секций и 100 ссылок в секции. Используется код без дополнительного LLM. Неподдержанный формат сохраняется как manual-review section, поля не додумываются.

Сохраняются title, категория и scope по явным правилам заголовка, текст summary/significance/limitations/priority/questions, rawSection, номера строк и ссылки, даты/версии/виды событий. Category/domain — результат heading rules, не подтверждённая научная классификация. Все эти значения происходят из вторичного обзора; `verification=unverified`. Partial date остаётся исходным текстом с flag, день месяца не придумывается. Предложенный priority не переносится в Story.score и не заменяет независимую человеческую разметку.

Есть два hash: `content_hash` соответствует точному первому полученному Markdown, `document_hash` нормализует только CRLF/CR в LF для idempotency paste/upload. Browser textarea/multipart может нормализовать переносы до получения сервером; файл читается как UTF-8 text. При повторе с другими переносами сохраняется первый оригинал. Значимые изменения текста создают новый original review; те же publication identities и events по-прежнему дедуплицируются.

Inline/reference-style links и bare DOI/arXiv нормализуются; tracking query/fragment удаляются из структурной ссылки, исходный адрес остаётся в original Markdown. DOI lowercased, arXiv версия хранится отдельно от canonical work ID. DOI извлекается из известных journal URL; link/identifier остаётся **primary candidate**, не проверенным paper или доказательством. News/blog/topic listing не превращается в первоисточник. Никакие URL не загружаются; нет PDF fetch, redirects, API enrichment, rendering HTML или исполнения инструкций обзора.

Scientific claims не создаются автоматически, quote/locator не фабрикуются. В extraction сохраняется текст вторичного пересказа; для evidence позднее нужен сам первоисточник. Извлечённые даты не перезаписывают Source.metadata с данными feed/API. Ссылки с неизвестной идентичностью и future subjects остаются сохранёнными без active Story.

## Идентичность, повтор и события

- Lookup использует canonical IDs и существующие aliases, а не title similarity. Независимые papers с одинаковым заголовком остаются отдельными.
- При нескольких публикациях в секции editor выбирает одну работу; остальные ссылки и версии остаются в extraction. Co-occurrence не создаёт DOI/arXiv alias. Подтверждение такой связи — задача первичной metadata verification.
- Known alias позволяет переиспользовать тот же Source/Story. Manual/feed/import используют те же source advisory locks. Транзакция импорта блокируется по document hash; повтор той же секции не создаёт items, events, editorial decisions или normalization jobs повторно.
- Дополнительная selection из прежнего обзора добавляет ранее не выбранные секции. Изменение уже подтверждённой identity под тем же original/item отклоняется, чтобы не переписать provenance.
- Виды reported events: initial_preprint, preprint_revision, journal_publication, experimental_result, independent_replication, correction, retraction, scientific_announcement. Они извлекаются из явных date/event labels, версии ссылки или названного события в заголовке. Пропущенное событие не выдумывается из общих рассуждений.
- Event identity включает существующую work identity, тип, дату/частичную дату и revision. Версия чужой публикации из той же секции не назначается выбранной работе без известного alias.
- Явный editor checkbox «Solicitar revisión» и **новое** событие переводят непубликовавшийся существующий сюжет в review через прежний record_selection; прежние причины сохранены. Reimport не запускает review второй раз. Для published story сохраняется pending event и отметка в каталоге; Article/Publication/approval не меняются.

## Изменения БД и API

Одна migration `202610300009_external_reviews.sql`, только academy:

- `external_reviews`: immutable оригинал, два hash, заявленный source_type, parser_version, автор/время импорта.
- `external_review_items`: immutable подтверждённые sections/extraction, identity, Story link либо future_scope/needs_identification, always-unverified.
- `scientific_events`: дедуплицированные reported events с ссылкой на первоначальный review item, needs_review и always-unverified.
- `import_external_review(text,text,text,jsonb)`: authenticated editor-only command. Direct table writes не выдаются; read RLS для существующих members, фиксированный search_path. Service-role не переносится в web. Невалидный batch откатывается целиком.

Source API меняется только добавлением чистого parser/normalizer. Existing create_candidate/record_selection, canonical Source/Story и publishing gates не заменяются. Для последующего enrichment есть canonical identities, Source links, нормализационные задания и неизменяемая claimed metadata. Existing feed ingestion может позже дополнить тот же Source через подтверждённые aliases. Автоматический lookup старых работ через journal/arXiv API здесь не запускается.

Migration 009 установлена **только локально**, без reset и изменения пользовательских candidates. Облако не изменялось; по последнему проверенному состоянию там 004, а 005–009 требуют отдельной reviewed установки. Git merge не устанавливает миграции и Vercel variables. При включении live production сначала пройти cloud setup из `EDITORIAL.md` и применить согласованные migrations.

## Доказательство и проверки

Основной fixture — настоящий предоставленный пользователем обзор 17–23 октября 2026: `tests/fixtures/weekly-review-2026-10-23.md`. Это raw secondary research material, а не утверждение истинности всех включённых научных результатов. Источники не перепроверяются сетью в CI.

- Unit: 10 научных секций; 4 active-scope / 6 future-scope, поля/locators, DOI/arXiv variants, partial dates, older preprint/journal event, unsafe URLs, unknown format, size limits. Нет model/network calls.
- pgTAP: роли/grants, original/item immutability, selection и повтор, active/future/missing-primary, разные papers при одинаковом title, events always-unverified, reopen ровно один раз, published content остаётся published.
- `npm run test:reviews:integration`: реальный исходный обзор импортируется через authenticated command в local transaction, seeded old arXiv match получает новый journal event, повтор возвращает те же identities, проверяются оригинал/hash и отсутствие новых verified claims. **Полный rollback** сохраняет пользовательскую БД. Отчёт — ignored `artifacts/review-import/demonstration.json`.
- `npm run test:editorial:web`: настоящие local Auth/Next Server Actions, paste и upload, preview без DB writes, selected confirm/reimport, переносы paste/upload, original archive, future/pending records, CSRF, reviewer/outsider и существующие inbox/catalog/budget сценарии. Собственные fixtures удаляются.
- Typecheck, unit suite, SQL suite, concurrency, production build и offline demo входят в общую проверку. Итоговые количества/результаты — `VALIDATION.md`.

## Ограничения и следующий PR

Parsing v1 ориентирован на данный стандартный English Markdown. Не разбивает автоматически несколько papers внутри одной секции, не создаёт semantic topic clusters и не устанавливает peer review из пересказа. Reviewer history/archive ограничен последними 50 обзорами. Reported-event review resolution и полноценный Historian ещё не реализованы.

Future-scope и missing-primary items сохранены, но ещё не имеют команды последующего перепривязывания immutable item к новой подтверждённой identity. Это требует отдельного lineage-preserving enrichment/link command. Повторное получение journal metadata и verified DOI↔arXiv linking — предлагаемый **SCI-002**: ограниченные primary metadata adapters и ручное разрешение pending identities. Это техническая подготовка content brief, не платный deep research. Затем — content package, голос и видео по `SPRINTS.md`.

HLD требует только небольшого дополнения о внешних вторичных обзорах, event lineage и future-scope archive; основная архитектура сохранена.
